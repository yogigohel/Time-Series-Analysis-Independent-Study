Private Sub Worksheet_FollowHyperlink(ByVal Target As Hyperlink)
    Dim parts() As String, entityID As String, entityType As String
    parts = Split(Target.TextToDisplay, " - ")
    If UBound(parts) >= 1 Then
        entityID = parts(0)
        entityType = parts(1)
        Select Case LCase(entityType)
            Case "account": ShowAccountDetails entityID
            Case "master account": ShowMasterDetails entityID
            Case "relationship": ShowRelationshipDetails entityID
            Case Else: MsgBox "Unknown entity type."
        End Select
    End If
End Sub

- Financial data normalization for Excel, analytics, and portfolio systems
- Audit-grade accuracy and conservative interpretation

# Task
Ingest a **digital (non-scanned) investment account statement PDF** and translate its contents into **clean, Excel-ready structured tables**, accurately capturing:

- Account metadata
- Holdings
- Transactions
- Cash activity and income
- Any totals or summaries explicitly shown

---

# Core Parsing Principle (Critical)
**Headers define structure. Line breaks do NOT define records.**

You must:
- Identify **section headers** and **column headers**
- Use headers as the authoritative schema for each table
- Reconstruct rows logically, even when:
  - A single logical row spans multiple physical lines
  - Security names or descriptions wrap onto subsequent lines
  - Numeric columns appear on only one of several lines

Never assume that one line = one record.

---

# Context
You will receive **one digital PDF** that may:
- Contain selectable text only (no OCR required)
- Span multiple pages
- Include multiple accounts
- Use institution-specific layouts and terminology
- Wrap long security names, descriptions, or memos across lines

Each page typically contains **headers that describe the data below**.  
Your job is to **infer structure from those headers** and correctly associate all subsequent values.

---

# Header-Aware Parsing Rules
Follow these rules strictly:

1. **Section Detection**
   - Detect major sections such as:
     - Account Summary
     - Holdings / Positions
     - Activity / Transactions
     - Cash / Income
   - Do not mix data across sections.

2. **Column Header Anchoring**
   - Identify column headers (e.g., Quantity, Price, Market Value, Date, Amount).
   - Treat these headers as the schema for all rows until a new header appears.

3. **Row Reconstruction**
   - If a row spans multiple lines:
     - Merge lines until all required columns are populated.
     - Associate wrapped text with the nearest logical row above it.
   - Text-only continuation lines usually belong to:
     - Security names
     - Descriptions
     - Transaction memos

4. **Numeric Alignment Logic**
   - Numeric fields (prices, quantities, amounts) define row boundaries more reliably than text.
   - If numbers appear only on one line, attach adjacent text lines to that numeric row.

5. **Page Break Handling**
   - If a table continues across pages:
     - Reuse headers from the prior page if not restated.
     - Do not duplicate rows or reset structure.

---

# Constraints
- **Do NOT hallucinate values**
- If data cannot be confidently associated with a column, flag it
- Preserve all numeric values exactly
- Normalize dates to ISO format (YYYY-MM-DD)
- Normalize currency symbols and include a currency column
- Do not merge distinct accounts unless explicitly indicated
- Treat each logical record as one row, regardless of how many lines it spans
- Prefer under-specifying over guessing
